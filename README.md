# GitHub Manager — веб-интерфейс для работы с репозиториями GitHub

[![PHP](https://img.shields.io/badge/PHP-7.4+-blue.svg)](https://www.php.net/)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

Одностраничное веб-приложение на чистом PHP и JavaScript: вход по GitHub Personal Access Token, список репозиториев,
просмотр веток и создание **независимых копий** репозиториев прямо из браузера. Без фреймворков, сборки и внешних
зависимостей — достаточно скопировать файлы на любой хостинг с PHP.

## ✨ Возможности

### 🔐 Авторизация
- Вход по GitHub Personal Access Token; токен проверяется запросом `GET /user`
- Токен хранится только в сессии PHP и никогда не передаётся в браузер
- CSRF-защита всех изменяющих запросов, выход из аккаунта одной кнопкой

### 📁 Репозитории
- Список ваших репозиториев: описание, язык, звёзды, форки, приватность, размер, дата обновления
- Поиск, фильтры (все / публичные / приватные / форки / копии), сортировка, подгрузка «Показать ещё»
- Переход к репозиторию на GitHub, удаление репозитория с подтверждением по имени
- Модальное окно со списком веток: поиск, отметка ветки по умолчанию, SHA, копирование имени

### 🍴 Создание форков и копий — три режима
| Режим | Что делает | Когда нужен |
|---|---|---|
| **Независимая копия** (по умолчанию) | Создаёт пустой репозиторий через API, клонирует оригинал (`git clone --bare`, все ветки и теги), отправляет все ссылки, выставляет ветку по умолчанию как в оригинале | Нужна полная история и независимость от оригинала |
| **Быстрая копия (архив)** | Скачивает архив выбранной ветки через API и делает один коммит | git недоступен на сервере, репозиторий очень большой, история не нужна |
| **Форк GitHub** | Один вызов `POST /repos/{owner}/{repo}/forks` | Нужен именно форк GitHub: быстро, но связан с оригиналом |

Копия — **обычный репозиторий в вашем аккаунте**: изменения в оригинале её не перетирают (в отличие от форка GitHub,
который остаётся связанным с источником). Существующий репозиторий по умолчанию не перезаписывается: имя проверяется
через API, а перезапись включается только явным флажком.

### 🎨 Интерфейс
- Три вкладки: **Репозитории**, **Мои форки**, **Состояние**
- Прогресс копирования по шагам с журналом, отменой и повтором упавшего шага
- Уведомления (тосты), модальные окна, скелетоны загрузки
- Адаптивная вёрстка, свайпы для переключения вкладок на телефоне, светлая и тёмная тема
- Вкладка «Состояние»: версии PHP/git/tar, доступность функций, права каталогов, лимиты GitHub API

## 🚀 Установка

### Требования
- PHP 7.4+ (проверено на PHP 8.5), расширения: `curl`, `json`, `mbstring`, `openssl`
- Для режима «Независимая копия»: `git` и разрешённые `proc_open()`/`exec()`
- Опционально: `tar` или расширение `phar` для распаковки архива (если нет ни того, ни другого, архивный режим
  распаковывается встроенным кодом)
- Веб-сервер: Apache (есть готовый [`.htaccess`](.htaccess)) или Nginx

### Шаг 1: Клонирование
```bash
git clone <URL-репозитория> github-manager
cd github-manager
```

### Шаг 2: Настройка
Скопируйте пример и поправьте под свой сервер:
```bash
cp config.local.php.example config.local.php
```
Каталог для рабочих данных (`data_dir`) должен быть **вне веб-каталога** и доступен на запись PHP: там живут клоны
репозиториев, задания и журнал копий. По умолчанию используется системный временный каталог.

### Шаг 3: Веб-сервер

Apache (файл `.htaccess` уже в комплекте):
```apache
<Directory /path/to/github-manager>
    AllowOverride All
    Require all granted
</Directory>
```

Nginx:
```nginx
server {
    listen 80;
    server_name your-domain.com;
    root /path/to/github-manager;
    index index.php;

    client_max_body_size 2m;
    # Копирование большого репозитория может идти дольше обычного запроса
    fastcgi_read_timeout 900;

    location ~ \.php$ {
        include snippets/fastcgi-php.conf;
        fastcgi_pass unix:/var/run/php/php8.2-fpm.sock;
    }

    location ~ /\.git { deny all; }
    location ~ ^/(lib|tests)/ { deny all; }
}
```

### Шаг 4: Токен GitHub
1. GitHub → Settings → Developer settings → Personal access tokens
2. Разрешения (fine-grained или classic):
   - `repo` — доступ к вашим репозиториям и их создание (для приватных источников),
     для публичных достаточно `public_repo`
   - `read:user` — профиль пользователя
   - `delete_repo` — только если хотите удалять репозитории из интерфейса
3. Вставьте токен в форму входа — он останется в сессии на сервере

## 🔧 Конфигурация

Настройки задаются файлом `config.local.php` (не попадает в Git) или переменными окружения — приоритет у переменных.

| Переменная | Ключ | Назначение |
|---|---|---|
| `GHM_API_BASE` | `api_base` | Адрес GitHub API (для GitHub Enterprise, например `https://ghe.example.com/api/v3`) |
| `GHM_GIT_HOST` | `git_host` | Хост git для авторизации (по умолчанию `https://github.com`) |
| `GHM_GIT_BINARY` | `git_binary` | Путь к git, если его нет в `PATH` |
| `GHM_TAR_BINARY` | `tar_binary` | Путь к tar |
| `GHM_CA_BUNDLE` | `ca_bundle` | Путь к корневым сертификатам, если автопоиск не сработал |
| `GHM_INSECURE_TLS` | `insecure_tls` | `1` — отключить проверку TLS (не рекомендуется) |
| `GHM_DATA_DIR` | `data_dir` | Каталог рабочих данных (вне веб-каталога) |
| `GHM_CLONE_TIMEOUT` / `GHM_PUSH_TIMEOUT` | `clone_timeout`, `push_timeout` | Таймауты операций git, сек (по умолчанию 900) |
| `GHM_API_TIMEOUT` | `api_timeout` | Таймаут запросов к API, сек |
| `GHM_BOT_NAME` / `GHM_BOT_EMAIL` | `bot_name`, `bot_email` | Кто автор коммита в архивном режиме |
| `GHM_DEMO` | `demo` | `1` — демо-режим на локальном макете GitHub (см. ниже) |

## 🧪 Тесты

Тесты не требуют интернета: рядом лежит макет GitHub API (`tests/mock_github.php`), который работает с настоящими
bare-репозиториями git, поэтому клонирование, отправка веток и тегов проверяются по-настоящему.

```bash
# Полный прогон: тесты сами поднимут макет и приложение (php -S)
php tests/run.php

# Если серверы уже запущены (например, в песочнице без php -S)
GHM_TEST_API_BASE=http://127.0.0.1:8090 \
GHM_TEST_APP_URL=http://127.0.0.1:8080 \
MOCK_GH_STATE=/tmp/ghm-mock php tests/run.php
```

Проверяются: валидация входных данных, маскирование токенов, CSRF, запуск процессов и git, клиент GitHub API
(пагинация, 401/404/409/422, PATCH, tarball, удаление), сквозное копирование во всех трёх режимах, хранилище заданий
и HTTP-API приложения.

### Демо-режим без токена

```bash
# 1) макет GitHub API (репозитории и git — настоящие, в локальном каталоге)
MOCK_GH_STATE=/tmp/ghm-mock php -S 127.0.0.1:8090 tests/mock_github.php

# 2) приложение в демо-режиме
GHM_DEMO=1 GHM_DEMO_TOKEN=demo-token GHM_API_BASE=http://127.0.0.1:8090 \
GHM_DATA_DIR=/tmp/ghm-data php -S 127.0.0.1:8080
```
Откройте `http://127.0.0.1:8080` — вход не потребуется, список репозиториев и копирование работают на локальном макете.

## 📖 Использование

### Первый вход
1. Откройте сайт в браузере
2. Введите логин GitHub и токен (логин должен совпадать с владельцем токена)
3. Нажмите «Войти»

### Вкладки
- **Репозитории** — ваши репозитории: поиск, фильтры, сортировка, кнопки «Ветки», «Создать форк», «Удалить»
- **Мои форки** — форки GitHub и копии, созданные этим приложением (с источником, режимом и статистикой)
- **Состояние** — диагностика сервера, подключения к GitHub API и лимитов запросов

### Создание копии (форка)
1. Найдите репозиторий и нажмите **«Создать форк»**
2. Укажите имя нового репозитория (по умолчанию `<имя>-copy`), режим и приватность
3. Нажмите «Начать копирование» — шаги выполняются по очереди, прогресс и журнал видны в окне
4. Готово: ссылка на новый репозиторий появится в окне и во вкладке «Мои форки»

### Просмотр веток
1. Нажмите «Ветки» на карточке репозитория
2. В окне — все ветки с SHA и веткой по умолчанию; клик открывает ветку на GitHub

## 🛡️ Безопасность

- Токен живёт только в сессии PHP; в HTML, JSON-ответах и логах он замаскирован
- Токен не попадает в аргументы командной строки: git получает его из файла конфигурации с правами `0600`
- Все изменяющие запросы защищены CSRF-токеном; сессия — `HttpOnly`, `SameSite=Lax`, идентификатор
  перегенерируется при входе
- Имена владельцев, репозиториев и ветки проверяются перед использованием в командах и путях
- HTML-вывод экранируется, ответы API отдаются только в JSON
- Рабочие каталоги и журналы создаются с правами `0700`/`0600`, удаляются после операций

### Рекомендации
- Используйте HTTPS для своего домена
- Не публикуйте `config.local.php` и держите `data_dir` вне веб-каталога
- Ограничьте доступ к `lib/`, `tests/` и `.git` (готово в `.htaccess`)
- Выдавайте токену минимально необходимые права и обновляйте его

## 🐛 Решение проблем

**«git недоступен на сервере»**
- Проверьте вкладку «Состояние»: версия git и доступность `proc_open`/`exec`
- Если хостинг запрещает запуск процессов, используйте режим «Быстрая копия (архив)» или «Форк GitHub»

**Ошибка TLS при обращении к git или API**
- Укажите путь к корневым сертификатам: `GHM_CA_BUNDLE=/etc/ssl/certs/ca-certificates.crt`
- Крайняя мера — `GHM_INSECURE_TLS=1` (небезопасно)

**Копирование обрывается по таймауту**
- Увеличьте `GHM_CLONE_TIMEOUT`/`GHM_PUSH_TIMEOUT` и таймауты веб-сервера (`fastcgi_read_timeout`, `proxy_read_timeout`)

**«Репозиторий уже существует»**
- Имя занято: выберите другое или поставьте флажок «Перезаписать, если имя занято»

**403/429 от GitHub**
- Исчерпан лимит запросов: посмотрите вкладку «Состояние» (сколько осталось и когда сбросится)
- Для приватных репозиториев нужен `repo` (или `public_repo` для публичных)

**Не удаётся удалить репозиторий**
- Нужно право `delete_repo` у токена и точный ввод имени репозитория в окне подтверждения
